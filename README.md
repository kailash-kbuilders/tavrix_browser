# Tavrix Browser

**Browse Beyond Limits.** A real mobile browser built with Flutter, Material 3
and the Android System WebView (Chromium).

Tavrix is not a WebView wrapper with fake buttons. Tabs are live WebViews,
history and bookmarks live in SQLite, downloads stream real bytes to disk with
true progress, and permissions are requested only when a feature needs them.

## Features

- **Browser shell** - address bar with URL/search detection, progress, security
  icon, swipe to switch tabs, long-press menu, back/forward/reload/stop/home.
- **Tabs** - unlimited tabs, live WebViews that never reload on switch, tab
  overview (grid and list), tab search, pin, groups, drag-free reorder, close
  all, recently closed with restore, session restore after restart.
- **Private browsing** - isolated `incognito` WebView sessions, separate tab
  list, no history written, optional wipe when the app goes to background.
- **Home** - speed dial with add/edit/delete/reorder, search engine selector,
  voice search, QR scan, recently closed, recent downloads, top sites.
- **Bookmarks** - folders (nested paths), favourites, search, edit, JSON export
  and import.
- **History** - grouped by day, search by URL/title/domain, single delete and
  range delete (hour/today/7 days/all).
- **Downloads** - real streaming downloads with progress, pause (keeps the
  partial file), resume via HTTP Range, cancel, retry, rename-safe duplicate
  handling, open and share, records in SQLite, Android notifications for
  progress/completion/failure.
- **Permissions** - a dedicated dashboard: Android OS permissions are requested
  contextually, and every website is decided separately. Camera and microphone
  requests from a page go through both layers.
- **Privacy** - HTTPS status, cookie clearing, local storage clearing, history
  clearing, site permission reset, Do Not Track, pop-up blocking, JavaScript and
  cookie switches.
- **Reader mode, find in page, desktop site, translate, offline pages,
  autofill from the password vault, share** - all wired to real behaviour.
- **Settings** - theme (light/dark/system), accent colour, toolbar position,
  font scaling, search engine, homepage, tabs, gestures, downloads,
  notifications, privacy, storage, backup and about. Every setting persists.
- **Password vault** - Android Keystore backed secure storage, strong password
  generator, per-site logins, form autofill by domain.

## Branding and app icon

The launcher icon is a real Android **adaptive icon**, not a square picture with
rounded corners baked in: `mipmap-anydpi-v26/ic_launcher.xml` layers a dark
gradient background under the logo mark, and the launcher applies its own shape
(circle, squircle, teardrop) on Android 8+. Legacy `ic_launcher.png` /
`ic_launcher_round.png` are generated for older devices, and
`drawable-*/ic_stat_tavrix.png` is the white notification glyph.

Source art: `assets/branding/logo_source.jpg`. Regenerate every size with:

```bash
python3 tools/generate_icons.py     # needs Pillow and numpy
```

The workflow copies `assets/android_icons/res/` into the generated Android
project, so the icons survive `android/` being regenerated.

## Architecture

```
lib/
  main.dart                 app bootstrap and providers
  app.dart                  MaterialApp, theme, font scaling
  models/                   plain data models (tab, bookmark, download, ...)
  providers/                state (ChangeNotifier): browser, settings,
                            bookmarks, history, downloads, permissions
  services/                 database (SQLite), settings storage, notifications,
                            permissions, browser engine, password vault
  screens/                  one file per screen
  widgets/                  address bar, toolbar, menu, tab card, webview stack
  utils/                    URL helpers, constants, navigation helper
  theme/                    Material 3 theme
```

The WebView is hidden behind `services/browser_engine.dart`, so the engine can be
replaced without touching the UI. Android-specific behaviour lives in the
workflow-generated manifest and in plugins, not sprinkled through the widgets.

## Run locally

You need the Flutter SDK (stable channel).

```bash
flutter pub get
flutter run
```

The `android/` folder is generated by the GitHub Actions workflow. To build
locally, run this once in the project root:

```bash
flutter create . --platforms=android,ios
```

iOS needs macOS with Xcode.

## Build the APK

Push to `main` and the **Build APK** workflow compiles a release APK and uploads
it as an artifact. Run the workflow manually (Actions -> Build APK -> Run
workflow) to also attach the APK to a GitHub Release named `apk-latest`.

The workflow:

1. generates `android/` in a throwaway project (never in place, so `lib/` and
   `pubspec.yaml` can never be overwritten),
2. enables Java desugaring required by `flutter_local_notifications`,
3. adds only the manifest permissions the app uses,
4. declares the intent queries `url_launcher` and `speech_to_text` need,
5. sets the application id and app label,
6. runs `flutter analyze`, `flutter test`, then
   `flutter build apk --release --no-shrink`.

## Tests

```bash
flutter test
```

Verified on Flutter 3.47.9: `flutter analyze` reports no issues and all 16 tests
pass.

`test/url_utils_test.dart` covers URL detection and search resolution,
`test/search_engine_test.dart` the engine templates, `test/download_item_test.dart`
the download model, and `test/widget_test.dart` the address bar.

## Known limitations

See [KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md) and
[FEATURE_CHECKLIST.md](FEATURE_CHECKLIST.md). The short version: the Android
System WebView does not expose Chrome extensions, native printing, or web push
from sites, and Tavrix says so instead of faking them.

## Permissions used

| Permission | Why |
| --- | --- |
| INTERNET | Load pages, search, download |
| ACCESS_NETWORK_STATE | Detect offline and network errors |
| POST_NOTIFICATIONS | Download progress/completion/failure notifications |
| CAMERA | QR scanning and site camera use (asked when used) |
| RECORD_AUDIO | Voice search and site microphone (asked when used) |
| ACCESS_COARSE/FINE_LOCATION | Sites that ask for location (asked when used) |
| VIBRATE | Optional haptic feedback |
| USE_BIOMETRIC | Declared for device-credential gated features |
| FOREGROUND_SERVICE / FOREGROUND_SERVICE_DATA_SYNC | Declared for background work; not started by default |

Tavrix never requests contacts, SMS, call logs, all-files access, overlay or
accessibility permissions.
